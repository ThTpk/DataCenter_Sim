# Data Center Simulator

เว็บจำลองการทำงานของ Data Center แบบ interactive สำหรับใช้สอนวิชา **Data Center & Cloud Computing**
ลากวางอุปกรณ์ ต่อสายไฟ / ท่อน้ำเย็น / สายสัญญาณ แล้วเห็นค่าพลังงาน ความร้อน PUE ความพร้อมใช้งาน
ระดับ Tier และต้นทุน อัปเดตแบบเรียลไทม์บนหน้าจอ

มีสองมุมมอง: **ผัง 2D** สำหรับออกแบบและต่อสาย กับ **ห้อง 3D** ที่หมุนดูอุปกรณ์จริงได้รอบด้าน
พร้อมเห็นการไหลของไฟฟ้า น้ำเย็น และข้อมูลวิ่งไปตามสายจริง

ทำงานบนเบราว์เซอร์ล้วน ไม่มี backend ไม่ต้องติดตั้งอะไร ไม่ต้องต่ออินเทอร์เน็ต

### การใช้งานพื้นฐาน

1. **วางอุปกรณ์** — ลากจากแถบซ้ายมาวางบนผัง (โซนที่ถูกต้องจะเรืองแสงขณะลาก)
2. **ติดตั้งอุปกรณ์ IT** — รายการที่มีแถบสีม่วงต้องลากไป **วางทับบนตู้ Rack** (เซิร์ฟเวอร์ GPU สตอเรจ ToR)
3. **ต่อสาย** — กดปุ่ม 🔌 ต่อสาย แล้วคลิกอุปกรณ์ต้นทาง → ปลายทาง (ระบบตรวจกฎการต่อให้ ถ้าต่อผิดจะบอกว่าต่อไปที่ใดได้บ้าง)
   หรือกด 🪄 **เชื่อมต่ออัตโนมัติ** ให้ระบบต่อตาม critical path
4. **เดินเวลา** — กดปุ่มเล่น แล้วกดเหตุการณ์ฝึกซ้อมในแท็บ "สรุประบบ"
5. **ดูรายละเอียด** — คลิกอุปกรณ์เพื่ออ่านสเปก หน้าที่ และประเด็นที่ต้องจำ

ปุ่มลัด: `Delete` ลบสิ่งที่เลือก · `Esc` ยกเลิกการต่อสาย

### มุมมองห้อง 3 มิติ

กดปุ่ม **🧊 ห้อง 3D** บนแถบเครื่องมือ จะเห็นห้องจริงแบบสามมิติที่หมุนดูได้รอบด้าน

| การควบคุม | ผล |
|---|---|
| ลากเมาส์ | หมุนกล้องรอบห้อง |
| Shift + ลาก (หรือคลิกขวาลาก) | เลื่อนตำแหน่งกล้อง |
| ล้อเมาส์ | ซูมเข้า-ออก |
| คลิกอุปกรณ์ | เลือกและเปิดรายละเอียดในแถบขวา |
| ลากจากคลังมาวางบนพื้น | เพิ่มอุปกรณ์ได้เหมือนในผัง 2D (อุปกรณ์ IT ลากไปวางทับตู้ Rack) |

มุมกล้องสำเร็จรูป: **ภาพรวม · ด้านหน้า · มุมบน · White Space · ห้องเครื่อง**
และเปิด/ปิดการแสดงผลแยกชั้นได้: สายไฟ · ท่อน้ำเย็น · สายสัญญาณ · การไหล · ป้ายชื่อ · โซน

สิ่งที่อ่านได้จากภาพ 3 มิติโดยตรง:

- **เส้นทางเดินสายจริง** — สายไฟอยู่บนรางเพดาน (ส้ม) ท่อน้ำเย็นเดินใต้พื้น (ฟ้า) สายสัญญาณอยู่รางบนสุด (เขียว)
- **การไหล** — จุดเรืองแสงวิ่งไปตามสายเฉพาะเส้นที่มีกระแสจริง เส้นที่ไม่มีไฟจะกลายเป็นเส้นประจาง
- **อุณหภูมิของตู้** — สีหลังคาตู้ไล่จากฟ้า (เย็น) → เหลือง → แดง (ใกล้จุดตัด 45 °C)
- **อุปกรณ์ในตู้** — ประตูตู้แสดงช่อง U จริง สีแยกตามชนิด (เซิร์ฟเวอร์ / GPU / สตอเรจ / ToR) และสว่างขึ้นตามการใช้งาน
- **ระดับแบตเตอรี่ UPS** — แถบไฟบนหน้าตู้ UPS เปลี่ยนเป็นสีแดงเมื่อเหลือน้อย
- **อุปกรณ์ที่ไม่มีไฟ / เสีย / ซ่อมบำรุง** — เปลี่ยนเป็นสีเทา สีแดง หรือสีเหลืองตามสถานะ

ตัวเรนเดอร์เขียนขึ้นเองบน Canvas 2D (painter's algorithm + back-face culling + flat shading)
จึงไม่ต้องพึ่งไลบรารีภายนอกและยังเปิดจากไฟล์แบบออฟไลน์ได้เหมือนเดิม

## เหตุการณ์ฝึกซ้อม (Drills)

กดได้จากแท็บ "สรุประบบ" ทุกเหตุการณ์มีคำอธิบายว่าควรสังเกตอะไร

- ไฟการไฟฟ้าดับ — ดูลำดับ UPS → Generator → ATS
- ไฟดับ + Generator สตาร์ทไม่ติด — นับเวลาจนแบตเตอรี่หมด (ประมาณ 22 นาทีจำลองที่โหลด 44%)
- Chiller เสีย 1 ชุด — ทดสอบว่า N+1 รับภาระไหวหรือไม่
- ความเย็นหายทั้งระบบ — thermal runaway อุณหภูมิถึงจุดตัด 45 °C ในราว 2 นาที
- UPS / PDU เสีย — ทดสอบเส้นทางไฟ A-side / B-side
- ตู้ Rack ล่มทั้งตู้ — ทดสอบ HA ของชั้น Cloud
- Core Switch ล่ม — "มีไฟ" ไม่เท่ากับ "ให้บริการได้"
- ทราฟฟิกพุ่ง 100% — autoscaling และผลต่อ PUE
- ซ่อมบำรุง UPS ตามแผน — ทดสอบคุณสมบัติ Concurrently Maintainable

ระบบจะฟื้นตัวเองเมื่อแก้ไขต้นเหตุ เช่น ซ่อมปั๊มแล้วตู้ที่ตัดจากความร้อนจะกลับมาทำงานเอง

## สูตรและแบบจำลองที่ใช้คำนวณ

ค่าทั้งหมดคำนวณจากโมเดล 3 ชั้นที่ต่อเนื่องกัน ไม่ใช่ตัวเลขที่กำหนดไว้ตายตัว

**ชั้น Cloud**

```
กำลังที่เซิร์ฟเวอร์ใช้ = idleW + (maxW − idleW) × utilization
utilization            = max(vCPU ที่ใช้จริง ÷ vCPU จริง,  GPU ที่จัดสรร ÷ GPU ทั้งหมด)
vCPU ที่ใช้จริง        = vCPU ที่จัดสรร × (0.35 + 0.65 × ทราฟฟิก)
```

**ชั้นไฟฟ้า**

```
โหลดของอุปกรณ์ต้นทาง = Σ (โหลดปลายทาง ÷ จำนวนเส้นทางจ่ายไฟที่ยังมีไฟ) ÷ ประสิทธิภาพ
การสูญเสีย           = ไฟเข้า − ไฟออก  (หม้อแปลง 1.5%, UPS 5%, PDU 1%)
เวลาที่แบตเตอรี่อยู่ได้ = พิกัดนาที ÷ (0.4 + 0.6 × สัดส่วนโหลด)
```

**ชั้นความร้อน**

```
ภาระความร้อน      = โหลด IT (ไฟฟ้าแปลงเป็นความร้อนเกือบ 100%)
ไฟที่ Chiller ใช้  = ความเย็นที่ผลิต ÷ COP_eff
COP_eff           = COP × (0.70 + 0.30 × min(1, PLR × 2))        ← ประสิทธิภาพตกที่โหลดต่ำ
                    และ × 1.45 สำหรับส่วนที่ระบายด้วย Liquid Cooling
ไฟปั๊ม/พัดลม       = พิกัด × (0.25 + 0.75 × PLR)                   ← VFD ปรับรอบตามโหลด
อุณหภูมิตู้         = เพิ่มขึ้นตามสัดส่วนความเย็นที่ขาด และความหนาแน่นของตู้
```

**ตัวชี้วัด**

```
PUE          = ไฟรวมทั้งอาคาร ÷ โหลด IT
             = (IT + ความเย็น + การสูญเสีย + ระบบประกอบอาคาร) ÷ IT
Availability = Π ทุกชั้น [ 1 − (1 − a)ⁿ ]        n = จำนวนอุปกรณ์สำรองในชั้นนั้น
Tier         = ประเมินจาก Generator + ATS, N+1 ทุกชั้น, จำนวนเส้นทางจ่ายไฟต่อตู้, 2N
```

ค่าเริ่มต้นของสภาพแวดล้อม: ค่าไฟ 4.2 บาท/kWh, ค่าการปล่อยคาร์บอน 0.4999 kgCO₂e/kWh,
อุณหภูมิเป้าหมาย 24 °C, ช่วงที่ ASHRAE แนะนำ 18–27 °C, จุดตัดอุปกรณ์ 45 °C

## แนวทางใช้สอน (กิจกรรมในห้องเรียน)

**คาบที่ 1 — รู้จักองค์ประกอบ**
เปิดแบบจำลอง Tier I แล้วให้นักศึกษาคลิกอุปกรณ์ทีละตัว อ่าน "หน้าที่ในระบบ" และ "ประเด็นที่ต้องจำ"
จากนั้นถามว่า ถ้าถอดอุปกรณ์ตัวนี้ออกจะเกิดอะไรขึ้น แล้วให้ลองลบจริงเพื่อดูคำตอบ

**คาบที่ 2 — critical path และความซ้ำซ้อน**
เปิด Tier I กดเหตุการณ์ "ไฟการไฟฟ้าดับ" ให้สังเกตว่าทำไมระบบถึงล่ม
แล้วให้นักศึกษาเพิ่ม Generator + ATS ทีละชิ้นจนรอดเหตุการณ์ (โจทย์ท้าทายข้อ 5)

**คาบที่ 3 — ความร้อนและความหนาแน่น**
เปิด AI Cluster เปรียบเทียบกับ Tier III ให้เห็นว่าทำไม GPU rack ต้องใช้ Liquid Cooling
ลองเปลี่ยน CDU เป็น CRAH แล้วดูอุณหภูมิไต่ขึ้นจนตู้ตัดตัวเอง

**คาบที่ 4 — PUE และต้นทุน**
ให้แข่งกันทำ PUE ให้ต่ำที่สุดภายใต้เงื่อนไขว่าต้องไม่มีข้อผิดพลาดสีแดง
เฉลยแนวทาง: Aisle Containment → Liquid Cooling → เพิ่มการใช้งานเซิร์ฟเวอร์ → ไม่ซื้ออุปกรณ์เกินจำเป็น

**คาบที่ 5 — Cloud Computing**
ใช้แท็บ Cloud เปรียบเทียบ Consolidate กับ Spread แล้วกดเหตุการณ์ "ตู้ Rack ล่มทั้งตู้"
พร้อมสลับเปิด/ปิด HA ให้เห็นจำนวน Workload ที่ดับต่างกัน และอธิบายว่าทำไม Cloud ต้องเผื่อกำลังสำรอง

**แบบฝึกหัด** — เปิดแบบจำลอง "ผังที่มีข้อผิดพลาด" ให้หาและแก้จุดบกพร่องทั้ง 5 จุด
(คำใบ้อยู่ในแท็บ "เหตุการณ์" ถ้าต้องการ)

## โครงสร้างไฟล์

```
index.html            โครงหน้าเว็บ
css/style.css         ธีมและเลย์เอาต์ทั้งหมด
js/catalog.js         ฐานข้อมูลองค์ประกอบ: สเปก คำอธิบาย ประเด็นสอน กฎการเชื่อมต่อ
js/engine.js          เครื่องคำนวณ: ไฟฟ้า ความเย็น อุณหภูมิ ความน่าเชื่อถือ Tier ต้นทุน Cloud
js/scenarios.js       แบบจำลองสำเร็จรูป เหตุการณ์ฝึกซ้อม โจทย์ท้าทาย บทเรียน
js/view3d.js          มุมมองห้อง 3 มิติ: กล้อง orbit, รูปทรงอุปกรณ์, เส้นทางสาย, การไหล
js/ui.js              ลากวาง ต่อสาย วาดผัง แดชบอร์ด สลับมุมมอง
.claude/launch.json   ค่าตั้งต้นสำหรับเปิด local server (ไม่จำเป็นต้องใช้)
```

### การปรับแต่งให้เข้ากับเนื้อหาที่สอน

- **แก้ตัวเลขอุปกรณ์** — แก้ `specs` ใน `js/catalog.js` ค่าทุกตัวถูกนำไปคำนวณทันที
- **เพิ่มองค์ประกอบใหม่** — เพิ่มรายการใน `DC.CATALOG` แล้วเพิ่มกฎการต่อสายใน `DC.RULES`
  และเพิ่มขนาดรูปทรงใน `GEO` ของ `js/view3d.js` เพื่อให้แสดงในมุมมอง 3 มิติด้วย
- **เพิ่มแบบจำลอง** — เพิ่มออบเจ็กต์ใน `P` ที่ `js/scenarios.js` (ใช้ `fill` เพื่อใส่เซิร์ฟเวอร์จำนวนมากในตู้เดียว)
- **เพิ่มโจทย์** — เพิ่มใน `SIM.CHALLENGES` โดยเขียนฟังก์ชัน `check(rt, model)`
- **แก้ค่าไฟหรือสภาพแวดล้อม** — แก้ `DC.ENV`

## ข้อจำกัดของแบบจำลอง (ควรบอกนักศึกษา)

โปรแกรมนี้ทำให้เข้าใจ *ความสัมพันธ์* ระหว่างองค์ประกอบ ไม่ใช่เครื่องมือออกแบบจริง จุดที่ลดทอนไว้:

- คิดอุณหภูมิเป็นค่าเดียวต่อตู้ ไม่มีการจำลองการไหลของอากาศหรือ hot spot จริง (ของจริงใช้ CFD)
- ความพร้อมใช้งานคิดแบบอนุกรม-ขนานอย่างง่าย ไม่รวม common cause failure และเวลาซ่อม (MTTR)
- ระบบจ่ายไฟคิดเป็นกำลังงาน (kW) ไม่คิดแรงดัน กระแส เฟส หรือ power factor
- ตัวจัดวาง Workload เป็น bin-packing อย่างง่าย ไม่มี affinity, taint/toleration หรือการย้ายงานแบบมีเวลา
- ราคาและค่าไฟเป็นค่าโดยประมาณเพื่อให้เห็นลำดับขนาด ไม่ใช่ราคาเสนอจริง
- ภาพ 3 มิติเป็นภาพเชิงสัญลักษณ์เพื่อสื่อความสัมพันธ์ ไม่ได้ย่อส่วนตามมาตราจริง
  ขนาดอุปกรณ์และระยะห่างจึงไม่ใช่ตัวเลขที่ใช้วางผังอาคารได้
